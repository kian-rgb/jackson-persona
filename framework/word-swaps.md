# The Word-Swap Table

Every entry here came out of a real edit in the Landjourney user guide. The rule is: if you see the left column in a draft, swap it for the right column.

---

## Layout & UI

| Avoid | Use instead | Why |
|---|---|---|
| sidebar | left menu / right side | "Sidebar" is a website word. Jackson sees a menu. |
| panel | section | Same thing, less jargon. |
| widget | section / card | "Widget" means nothing to a loan officer. |
| overlay | window on screen | Describes what he actually sees. |
| modal / dialog | pop-up window / window | Universally understood. |
| toolbar | controls bar | "Bar of controls" is the mental model already. |
| breadcrumb | path (or describe what it does) | Nobody calls it a breadcrumb outside dev. |

---

## Actions

| Avoid | Use instead | Why |
|---|---|---|
| toggle | switch / turn on / turn off | Verbs Jackson uses; noun he recognizes. |
| authenticate | sign in | Every login screen in his life says "sign in." |
| configure | set up / fill in | Plain-English equivalent. |
| navigate to | go to / open | Same as browser buttons. |
| threaded | organized by task / by conversation | "Threaded" is Slack/Reddit vocabulary. |
| paginated | split across multiple pages | Descriptive, not abstract. |

---

## Objects & concepts

| Avoid | Use instead | Why |
|---|---|---|
| wizard | setup process / setup | "Wizard" is a Windows 95 word. |
| dynamic form | online form | "Dynamic" adds nothing for Jackson. |
| rich text editor | message box / text box | It's just a box he types into. |
| document viewer | on screen / full-page view | Describes what he sees. |
| reusable configurations | saved setups | "Configurations" is engineering vocabulary. |
| structured data | information | The word "structured" is not load-bearing here. |
| pan tool | move around the document | Describes the action. |
| annotation tools | mark up tools | "Annotate" is niche vocabulary. |

## Adjectives that add nothing

| Avoid | Use instead | Why |
|---|---|---|
| dynamic | (usually cut it) | Adjective loved by product marketing, invisible to users. |
| layered | (usually cut it) | Same. |
| streamlines | simplifies | Simple word does the job. |
| empowering | (cut it) | Marketing-speak. |
| leverages | uses | Same meaning, no jargon points lost. |

---

## Section title patterns

| Avoid | Use instead | Why |
|---|---|---|
| "Backoffice — Discussions" | "Discussions" | The nav already tells Jackson what section he's in. |
| "@ Mentions" | "Tagging People" | Nobody says "at mentions" out loud. |
| "Viewing Discussion History" | "Viewing Past Messages" | Says exactly what you'll see. |
| "Messenger vs. Discussions" | "When to Use Discussions vs. Messenger" | Gives the reader a decision, not a comparison. |

---

## What NOT to swap

Not everything technical needs to go. Keep terms that are:

- **Named things in the product UI.** If the button says "Change Stage," write "Change Stage" — don't invent your own phrasing.
- **Industry vocabulary Jackson already uses.** Guarantor, co-borrower, collateral, disclosure, closing — leave these alone.
- **Compliance and legal terms.** SOC 2, TLS, encryption, audit trail — Jackson has heard these from his compliance officer. They belong.
- **Words the app itself uses on-screen.** Consistency with the UI beats "clearer" phrasing every time.

The goal is Jackson-comprehension, not dumbing down. He is smart. He is not a software person.
